# AETHERIA: ECHOES OF THE VOID

GitHub Pagesでサーバーレス配信される、ブラウザ完結型の3Dオープンワールド・アクションRPGです。
明るいトゥーンシェーディングの世界観で、`index.html` を開くだけで遊べます（インストール不要・ログイン不要）。

## 遊び方

1. `index.html` を開く（またはGitHub Pagesの公開URLへアクセス）
2. タイトル画面で「物語を始める」→ 広大なハブワールドに降り立つ
3. WASD/仮想スティックで歩き回り、光る目印に近づくと自動で聖域のストーリーへ
4. 依頼人NPCに話しかけてクエストを受注し、数百m先の討伐目標を倒して報告する、採取ポイントを拾う、
   石碑を読むなど、オープンワールド上で実際に発見・攻略する
5. 商店で結晶の欠片を武器・防具と交換。マップ画面(🗺)で聖域・依頼人・討伐目標・自機位置を確認できる
6. 「結晶獣と戦う」でボス戦へ。攻撃・強攻撃・結晶技・ガード／パリィ・回復を駆使して勝利を目指す
7. 章をクリアすると経験値・結晶の欠片を獲得し、装備やスキルツリーを強化できる
8. 最終章クリア後、集めた結晶の欠片の量に応じて複数のエンディングから結末を選べる

進行状況はブラウザの `localStorage` に自動保存され、タイトル画面の「つづきから」でいつでも再開できます。

## 世界観・ストーリー

神々の血「エーテル」によって繁栄した星エセリア。過剰な採掘が空間の亀裂「ヴォイド」を生み、
生きとし生ける者を鉱物に変える「結晶病」が世界を蝕んでいる。右腕を漆黒の結晶に侵された
記憶喪失の剣士「アッシュ」は、案内人イリスと共に、世界を支える大結晶「プライム・コア」を
目指して聖域を巡る旅に出る――。

| 聖域 | 敵 | 概要 |
|---|---|---|
| 聖域 I | 軋みの番人 | 崩壊の古城を彷徨う結晶化した騎士像 |
| 聖域 II | 棘毒のドライアス | 結晶の森に取り憑いた元・生命の守護霊 |
| 聖域 III | 反響するアーカイヴィスト | 浸食された地下都市の詠唱者 |
| 聖域 IV | ヴォイド・エコー | すべての元凶。アッシュ自身の残響（覚醒フェーズあり） |

## 主な機能

- **オープンワールド探索**: 半径12,000mのハブワールドを三人称視点で自由に歩き回れる
- **実質的なクエストシステム**: 探索(採取)／討伐(簡易スキルミッシュ)／ロア(石碑)の3種を実際に現地で攻略
- **商店・マップ**: 結晶の欠片で装備を購入。マップ画面で聖域・依頼人・討伐目標・自機位置を確認
- **本格RPG進行**: 全4聖域のストーリー、レベルアップ、聖域ごとに異なる敵ビジュアル・攻撃パターン
- **装備システム**: 武器・防具・装飾の3スロット。攻撃力／防御力／クリティカル率／HP／エーテルに反映
- **スキルツリー**: 結晶の欠片を消費してパッシブ能力を解放（攻撃/防御強化、パリィ強化、蘇生など）
- **パリィ機構**: ガードのタイミングを見極めてジャストガードすれば、大ダメージの反撃カウンターが発生
- **マルチエンディング**: 累計で集めた結晶の欠片の量によって、選べるエンディングが変化（隠し真エンディングあり）
- **ライト基調のトゥーンシェーディング**: 明るい空とセルルック調のキャラクター、輪郭線付き
- **フルポストプロセッシング**: Bloom/SSAO/被写界深度/フィルムグレイン/色収差/SMAA
- **セーブ／ロード**: localStorageによる自動保存・つづきから再開
- **モバイル完全対応**: iPhoneなどスマホでも大きく見やすいレスポンシブUI、仮想スティック操作
- **グラフィック品質設定**: HIGH/MEDIUM/LOWでピクセル比・シャドウ・ポストFXを実際に切り替え可能

## プロジェクト構成

```
index.html         エントリーポイント（HTML構造のみ）
css/
  style.css         HUD・画面レイアウト全般
  menu.css          ガラスモーフィズムのポーズメニュー
js/
  data.js           ストーリー・クエスト・アイテム・スキルのコンテンツ定義
  state.js          実行時ステート、装備/スキル計算、セーブ／ロード
  scene.js          Three.jsシーン・カメラ・ライティング・ポストFX・闘技場
  world.js          オープンワールド(地形・聖域・NPC・商店・討伐目標)の生成
  explore.js        探索モードの移動・三人称カメラ・インタラクション判定
  skirmish.js        フィールド討伐目標との簡易スキルミッシュ
  enemy.js          敵キャラクターのプロシージャル生成
  player.js         プレイヤーglTFモデルの読み込み・アニメーション
  effects.js        パーティクル・ダメージ数値・カメラシェイク
  audio.js          Web Audioによる効果音・BGM風シンセ
  combat.js         戦闘ロジック（攻撃・パリィ・フェーズ・勝敗判定）
  ui.js             HUD・メニュー・クエストボードのDOM描画
  main.js           全体の初期化・画面遷移・レンダリングループ
tools/              開発時の静的検査スクリプト（実行時には読み込まれない）
vendor/             Three.js本体とGLTFLoader、ポストプロセッシング等（実ファイル、CDN非依存）
assets/models/      プレイヤーモデル（glTFバイナリ）
```

## 開発時の検査

バンドラもテストランナーも使わず、ブラウザが直接 ES モジュールを読む構成のため、
壊れ方の多くは「実行して該当画面に到達するまで気づけない」種類になる。
変更後は以下を通すことで早期に検出できる。

```
node tools/check-all.mjs
```

内訳（個別にも実行できる）:

| ツール | 検査内容 |
| --- | --- |
| （check-all に内蔵） | `js/` 全ファイルの構文チェック |
| `tools/check-imports.mjs` | 相対 import が実在する export を指しているか |
| `tools/check-save-fields.mjs` | state の既定値・保存・復元の対応漏れ |
| `tools/check-achievements.mjs` | 実績の定義・解除判定・進捗バーの対応 |
| `tools/check-data.mjs` | 章・装備・スキル・ショップなどデータ間の参照整合性 |

`state` に項目を追加するときは **既定値・`saveGame`・`loadGame` の3箇所**すべてに
書く必要がある。`check-save-fields.mjs` はこの書き漏らしを検出する。
意図的に保存しない項目は同スクリプトの `TRANSIENT` に理由付きで列挙する。

> 補足: `node --check foo.js` は、対象が ESM の `import` を含むと構文エラーがあっても
> 終了コード 0 を返す。そのため検査は `--input-type=module` を用いている。

## 技術構成

- [Three.js](https://threejs.org/)（r152）によるWebGL 3Dレンダリング。ES Modules + importmapで構成
- トゥーンマテリアル＋輪郭線によるセルルック、フルポストプロセッシングパイプライン
  (SSAO/Bloom/被写界深度/フィルムグレイン/色収差/ビネット/SMAA)
- 効果音はWeb Audio APIでリアルタイム生成（外部音源ファイル不要）
- 進行状況はlocalStorageに保存（サーバー不要）
